🛠️快速排查步骤：
1
检查系统本地时间：时间不同步会导致 TLS 握手失败，误差需在 60 秒以内；进入系统设置点击「立即同步时间」。
2
检查客户端核心与系统代理：确认核心状态处于 Running，且系统代理开关（System Proxy）或 TUN 虚拟网卡已正常开启。
3
更新订阅链接排查域名变更：服务商可能已更换解析域名或连接端口，点击客户端「Update Subscription (更新订阅)」重新获取最新节点。
💡 简明结论： 通常是客户端版本过旧不支持新协议链接，或订阅源被运营商本地阻断。
🛠️快速排查步骤：
1
开启系统已有网络全局访问：开启系统已有可用网络或热点后再尝试更新订阅，排查本地运营商对订阅分发域名的 DNS 阻断。
2
升级客户端至最新内核版本：老版本客户端不支持最新的 VLESS-Reality、Hysteria2 或 Sing-box 订阅语法，请升级至最新版。
3
在服务商后台转换订阅格式：在服务商后台选择客户端专属一键导入，或使用订阅转换工具（如将 V2Ray 转换为 Clash/Sing-box 规则格式）。
💡 简明结论： 本地系统代理端口被其他软件占用，或者客户端内核异常崩溃退出。
🛠️快速排查步骤：
1
重启客户端确认核心进程：重启客户端，确认内核进程（clash-core/sing-box）未被 Windows Defender 或第三方杀毒软件误杀。
2
检查本地混合端口占用：检查默认端口（如 7890 / 10808）是否被其他下载器、虚拟机或抓包软件占用，可在设置中改为其他端口。
3
重置网络套接字与代理残留：在管理员终端执行 netsh winsock reset，或在 Windows 网络设置中关闭并重置手动代理服务器。
💡 简明结论： 系统根证书库过期、开启了 MITM 抓包拦截、或内网存在 HTTP 代理劫持。
🛠️快速排查步骤：
1
更新操作系统根证书库：旧版系统缺少最新根证书，打齐系统补丁或手动导入更新根证书（如 ISRG Root X1）。
2
关闭抓包工具与杀软流量扫描：关闭 Fiddler、Charles、Proxyman 等抓包工具，并检查杀毒软件是否开启了 SSL/TLS 流量嗅探过滤。
3
客户端临时开启跳过证书校验：在客户端高级设置中临时开启「跳过证书校验 (skip-cert-verify)」排查，若能连上则尽快修复本地证书。
💡 简明结论： 误开了「全局代理」让国内流量绕道海外，或 DNS 发生污染导致国内域名被解析为海外 IP。
🛠️快速排查步骤：
1
切换路由模式为规则分流：将路由模式从「全局 (Global)」切换为「规则分流 (Rule / PAC)」，确保国内应用与网站直连（DIRECT）放行。
2
开启 Fake-IP 并配置纯净国内 DNS：在客户端开启 Fake-IP 模式，将国内 Direct DNS 解析服务器指定为 223.5.5.5 或 119.29.29.29。
3
刷新本地 DNS 缓存：打开终端执行 ipconfig /flushdns（macOS 为 dscacheutil -flushcache）清理污染解析残留。
💡 简明结论： 这部分网站对 IP 地域判定极为严格，且客户端规则库未将其收录，导致流量被错误代理或触发防重放安全策略。
🛠️快速排查步骤：
1
将目标域名加入直连规则 (DIRECT)：在客户端自定义规则中添加 DOMAIN-SUFFIX,xxx.edu.cn,DIRECT，确保该机构域名完全直连。
2
暂停 TUN 模式或使用纯系统代理：部分网银客户端会检测是否存在虚拟网卡驱动（Wintun），办理业务前可临时关闭 TUN 虚拟网卡。
3
关闭防泄漏中的严格安全劫持：关闭针对国内域名的强制 DOH 劫持，防止国内专用服务因无法获取真实运营商内网 IP 而报错。
💡 简明结论： 本地多网卡或备用 DNS 将海外域名解析请求广播给了国内运营商，造成访问行为明文泄漏。
🛠️快速排查步骤：
1
使用专门测试网站进行验证：访问 dnsleaktest.com 进行 Extended Test 扩展测试，若测试列表中出现国内 ISP 的 DNS 即存在泄漏。
2
开启远端加密 DNS 解析：将分流规则中的海外域名 DNS 查询绑定至代理通道（Nameserver-Policy），使用纯净远端加密解析并关闭并发回退。
3
禁用智能多宿主名称解析：在 Windows 组策略中启用「关闭智能多宿主名称解析」，防止系统绕过代理向本地多网卡广播 DNS。
💡 简明结论： Fake-IP 速度快、抗污染好，适合 95% 的网页与流媒体；Redir-Host 兼容真实 IP，适合部分对虚拟 IP 敏感的外服游戏与局域网设备。
🛠️快速排查步骤：
1
日常浏览与视频首选 Fake-IP：Fake-IP 模式下客户端直接向应用返回 198.18.x.x 虚拟 IP，省去本地 DNS 握手等待，网页秒开体验极佳。
2
外服游戏联机排查：部分硬编码 IP 或反作弊游戏检测到 198.18 段虚拟 IP 会无法连入，可切为 Redir-Host 或添加游戏进程直连。
3
BT / PT 下载严禁走代理通道：在客户端中务必将 BitTorrent、qbittorrent 下载流量配置为 DIRECT 直连，避免 Fake-IP 虚拟映射污染内网或被机场封禁。
💡 简明结论： 夜间跨洋骨干网总带宽超载触发了运营商 QoS 丢包限速。普通公网直连首当其冲，换专线内网或抗拥塞协议可保平安。
🛠️快速排查步骤：
1
理解公网骨干网丢包机制：普通 163 或 4134 骨干网在高峰期丢包率可达 20%~40%，传统 TCP 拥塞控制遭遇丢包会断崖式降速。
2
切换专线/优质中继节点：建议在晚高峰优先切换为具备 BGP 优质入口或 IPLC/IEPL 内网专线中继的节点，完全绕开公网拥堵点。
3
换用抗丢包新型传输协议：在协议设置中调整为抗丢包能力更强的新型协议（如基于 UDP 的 Hysteria2，或在节点服务端开启 TCP BBR 拥塞控制）。
💡 简明结论： 客户端默认测的是「本地到国内中继入口」的 TCP 握手延迟，不代表海外落地机房到目标网站的真实加载速度。
🛠️快速排查步骤：
1
区分入口延迟与真实落地延迟：专线节点的 Ping 往往只是测本地宽带到国内入口机房的时间，若境外落地机房拥堵，网页依然会卡顿。
2
将测试 URL 设为真实海外网站：在客户端设置中将延时测试的 URL 从默认的 gstatic 改为真实海外目标（如 https://www.google.com/generate_204）。
3
观察节点带宽负载与吞吐：在测速页面使用测速冰箱跑一次真实下载速率，有些节点延迟极低但峰值带宽已被合租用户跑满挤爆。
💡 简明结论： 目标平台具备严格的商业 IP 风险库，若节点 IP 属于托管机房数据中心（Hosting/DCH）便会被拦截，需要纯净原生家宽 IP 落地。
🛠️快速排查步骤：
1
确认节点是否标有专用解锁标识：在节点列表中切换为标注有「原生 IP」或专门标有对应流媒体解锁标识（如 🍿NF / 🏰DP / 🤖OpenAI）的落地节点。
2
检查是否使用了家庭住宅落地中继：流媒体风控服务商会将机房 IP 标记为高风险，优质服务商通常会挂载 Residential 住宅原生 IP 解锁。
3
彻底清理浏览器缓存与 Cookie：清除浏览器中该网站的历史 Cookie 与 LocalStorage，或打开无痕/隐私窗口重新登录，防止因历史指纹残留被判定为代理。
💡 简明结论： 常规多线程测速能堆满瞬时突发带宽，但视频点播依赖单线程长连接的持续稳定性与境外 CDN 路由质量。

1
警惕多线程测速假象：Speedtest 是通过 8~16 个并发请求测出的峰值，而油管/网飞通常使用单线程分片传输，受限于单流 TCP 拥塞窗口。
2
打开视频详细统计信息：在 YouTube 视频上右键打开「Stats for nerds (详细统计信息)」，观察 Connection Speed 是否稳定在 50000 Kbps 以上及 Buffer Health 缓冲长度。
3
检查运营商 UDP QoS 限速：若使用的是基于 UDP 的协议，部分省份宽带会对长时间持续高带宽的 UDP 流量施加阻断或限速，可尝试切回 TCP 协议排查。

1
iOS 端关闭低电量并检查按需连接：关闭系统「低电量模式」；在 Shadowrocket / Loon 设置中确保「按需连接 (On Demand)」配置正确，防止系统回收 TUN 网卡。
2
Android 端解除电池优化并锁定任务：在系统设置中将客户端的省电策略设为「无限制 / 不优化」；并在多任务界面将应用卡片下拉「加锁」。
3
开启客户端前台守护通知：在客户端应用设置中开启「保持后台连接」及「前台服务常驻通知栏（唤醒守护）」开关，提升系统进程优先级。

🛠️快速排查步骤：
1
勾选绕过私有局域网：在客户端 TUN 设置中，确保开启「Bypass Private Networks（绕过私有网络地址）」选项。
2
手动添加局域网直连网段：若仍无法连接 NAS，在自定义分流规则中加入：IP-CIDR,192.168.0.0/16,DIRECT,no-resolve 及 IP-CIDR,10.0.0.0/8,DIRECT,no-resolve。
3
排除第三方虚拟网卡冲突：若安装了虚拟机（VMware/VirtualBox）或 Docker，检查其网段是否与 TUN 默认网段（如 198.18.0.0/16）重叠，如有重叠需修改 TUN 接口网段。

🛠️快速排查步骤：
1
手动关闭 Windows 系统代理开关：打开 Windows 设置 →「网络和 Internet」→「代理」，关闭「使用代理服务器」开关并保存。
2
养成通过软件托盘正常退出的习惯：避免在任务管理器中强制杀死进程，在软件菜单中点击「Quit / 退出」时，客户端会自动清理系统代理注册表残留。
3
应急一键恢复小技巧：重新打开客户端软件，先开启系统代理，再正常点击「退出」或在系统 Internet 选项「局域网设置」中取消勾选代理。
